\chapter*{REZUMAT}
\addcontentsline{toc}{chapter}{Rezumat}
\vspace*{0.5cm}

\noindent\textbf{Recon-Platform-R2} este un dispozitiv portabil de
cartografiere a spațiilor interioare construit în jurul unui senzor LIDAR
2D \textit{LD14P} (LD-D200), al unui calculator pe o singură placă
\textit{Raspberry Pi~5} și al unui microcontroler coprocesor \textit{ESP32}.
Operatorul poartă dispozitivul prin spațiul de scanat, iar aplicația
construiește în timp real o hartă bidimensională sub formă de
\textit{occupancy grid}, folosind algoritmul \textit{Karto SLAM} prin
pachetul \texttt{slam\_toolbox} din \textit{ROS2 Jazzy Jalisco}. Estimarea
orientării este derivată din integrarea giroscopică a unui IMU
\textit{MPU-6050} prin pachetul \texttt{robot\_localization} (filtru Kalman
extins în mod 2D). Datele LIDAR sunt transportate de la senzor către
\texttt{slam\_toolbox} printr-o cale neconvențională în care ESP32-ul
acționează ca repetor USB-CDC, cu o pseudo-terminal (PTY) Linux pe partea
Pi care emulează un port serial real pentru driverul de LIDAR. Hărțile
salvate sunt persistate într-o instanță PostgreSQL containerizată Docker
și pot fi procesate ulterior printr-un pipeline pur-NumPy ce aplică
filtru median, operații morfologice, etichetare a componentelor conectate
și transformata Hough probabilistică pentru detecția pereților. Interfața
de utilizator este o aplicație web Flask + SocketIO accesibilă printr-un
punct de acces WiFi propriu, expus prin \texttt{hostapd} și \texttt{dnsmasq}.

\medskip

\noindent\textbf{Cuvinte cheie:} SLAM, LIDAR 2D, ROS2 Jazzy Jalisco,
fuziune senzorială, EKF, ESP32, Raspberry Pi 5, transformata Hough,
PostgreSQL, Flask-SocketIO.

\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{Abstract}
\vspace*{0.5cm}

\selectlanguage{english}
\noindent\textbf{Recon-Platform-R2} is a handheld indoor mapping device
built around a 2D \textit{LD14P} (LD-D200) LIDAR sensor, a
\textit{Raspberry Pi~5} single-board computer, and an \textit{ESP32}
coprocessor microcontroller. The operator carries the device through the
target space while the application builds a real-time 2D occupancy grid
using the \textit{Karto SLAM} algorithm via the \texttt{slam\_toolbox}
package on \textit{ROS2 Jazzy Jalisco}. Heading estimation is derived
from gyroscopic integration of an \textit{MPU-6050} IMU through the
\texttt{robot\_localization} package (extended Kalman filter in 2D mode).
LIDAR data reaches \texttt{slam\_toolbox} via an unconventional path in
which the ESP32 acts as a USB-CDC relay, with a Linux pseudo-terminal
(PTY) on the Pi side emulating a real serial port for the LIDAR driver.
Saved maps are persisted in a Docker-containerised PostgreSQL instance
and can be post-processed by a pure-NumPy pipeline that applies median
filtering, morphological operations, connected-component labelling, and
the probabilistic Hough transform for wall detection. The user interface
is a Flask + SocketIO web application served over a self-hosted WiFi
access point through \texttt{hostapd} and \texttt{dnsmasq}.

\medskip

\noindent\textbf{Keywords:} SLAM, 2D LIDAR, ROS2 Jazzy Jalisco, sensor
fusion, EKF, ESP32, Raspberry Pi 5, Hough transform, PostgreSQL,
Flask-SocketIO.

\chapter{Introducere}
\label{cap:introducere}

Cartografierea spațiilor interioare reprezintă o problemă recurentă în
domenii care variază de la robotica de servicii și sistemele de asistență
arhitecturală până la jocurile de tip ,,scanare a unei camere și
exportarea modelului 3D'' din industria divertismentului interactiv.
Soluțiile comerciale existente sunt fie costisitoare (scanere laser
profesionale, cu prețuri în mii de euro), fie incomode (aplicații pentru
smartphone bazate pe LIDAR-ul ToF, cu acuratețe limitată și dependență de
ecosistemul iOS/Android). Proiectul \textit{Recon-Platform-R2} își propune
să demonstreze că un dispozitiv portabil, autonom (cu propria rețea WiFi)
și open-source poate produce hărți 2D de calitate utilizabilă la un cost
hardware total sub 200~EUR.

\section{Algoritmul Karto SLAM și optimizarea grafului de poze}
\label{sec:karto}

\textit{slam\_toolbox}~\cite{macenski2021slamtoolbox} folosește algoritmul
\textbf{Karto SLAM}~\cite{konolige2010karto}, un sistem 2D bazat pe
optimizarea unui graf de poze. Diagrama logică a algoritmului este:

\begin{enumerate}\itemsep0pt
    \item achiziție scanare LIDAR (\textit{cadru curent});
    \item potrivire (\textit{scan matching}) a cadrului curent față de
          ultimele $k$ cadre cheie (\textit{keyframes});
    \item dacă mișcarea de la ultimul cadru cheie depășește un prag, se
          adaugă cadrul curent ca nou nod în graf;
    \item căutare de potriviri pentru închidere de buclă (\textit{loop
          closure}) cu cadre cheie distante geometric;
    \item optimizare a întregului graf cu un rezolvitor de probleme
          neliniare ale celor mai mici pătrate
          (\textit{Ceres}~\cite{ceres_solver}).
\end{enumerate}

[De dezvoltat: introducerea formală a problemei SLAM ca probabilitate
condiționată, formularea ca optimizare a grafului de poze, ecuațiile
celor mai mici pătrate.]

% Formula 1 — costul SLAM ca optimizare a grafului de poze
\begin{equation}\label{eq:slam-cost}
    \mathbf{x}^{*} = \arg\min_{\mathbf{x}}
        \sum_{(i,j) \in \mathcal{E}}
            \left\| \mathbf{e}_{ij}(\mathbf{x}_i, \mathbf{x}_j, \mathbf{z}_{ij}) \right\|^{2}_{\boldsymbol{\Omega}_{ij}}
\end{equation}

\noindent unde $\mathbf{x}_i$ sunt pozele estimate, $\mathbf{z}_{ij}$
sunt măsurătorile relative dintre cadrele cheie $i$ și $j$,
$\boldsymbol{\Omega}_{ij}$ este matricea informației (inversa
covarianței), iar $\mathbf{e}_{ij}$ este eroarea reziduală.

\section{Filtre Kalman extinse pentru fuziune senzorială}
\label{sec:ekf}

[De dezvoltat: ecuațiile predicție / actualizare ale EKF, particularizate
pentru cazul Recon-Platform-R2 unde vectorul de stare $\mathbf{x} = [\theta, \dot{\theta}]^T$
(modul \texttt{two\_d\_mode} cu doar yaw și yaw-rate activate, vezi
\texttt{config/ekf.yaml}). Referințe:
Kalman~\cite{kalman1960}, Welch~\&~Bishop~\cite{welchbishop2006kalman},
robot\_localization~\cite{moore2014robotlocalization}.]

% Formula 2 — pas predicție EKF
\begin{equation}\label{eq:ekf-predict}
    \hat{\mathbf{x}}_{k|k-1} = \mathbf{f}(\hat{\mathbf{x}}_{k-1|k-1}, \mathbf{u}_k)
\end{equation}

% Formula 3 — pas actualizare EKF
\begin{equation}\label{eq:ekf-update}
    \hat{\mathbf{x}}_{k|k} = \hat{\mathbf{x}}_{k|k-1}
        + \mathbf{K}_k \left(\mathbf{z}_k - \mathbf{h}(\hat{\mathbf{x}}_{k|k-1})\right)
\end{equation}

\noindent cu câștigul Kalman:

\begin{equation}\label{eq:kalman-gain}
    \mathbf{K}_k = \mathbf{P}_{k|k-1} \mathbf{H}_k^T
        \left(\mathbf{H}_k \mathbf{P}_{k|k-1} \mathbf{H}_k^T + \mathbf{R}_k\right)^{-1}
\end{equation}

\section{Integrarea giroscopică și conversia în cuaternioni}
\label{sec:giro}

Nodul \texttt{imu\_yaw\_integrator} (Python) integrează componenta
$\omega_z$ a vitezei unghiulare a IMU-ului pentru a produce un unghi de
cap $\theta$. Având în vedere că dispozitivul scanează într-un plan
orizontal, doar componenta $z$ este relevantă:

\begin{equation}\label{eq:yaw-integrate}
    \theta_n = \theta_{n-1} + \omega_{z,n} \cdot \Delta t
\end{equation}

Conversia rezultatului în cuaternion (cerere a interfeței
\texttt{sensor\_msgs/Imu} pentru \texttt{slam\_toolbox}):

\begin{equation}\label{eq:yaw-to-quat}
    \mathbf{q} = \left( 0,\; 0,\; \sin\left(\frac{\theta}{2}\right),\; \cos\left(\frac{\theta}{2}\right) \right)
\end{equation}

[De dezvoltat: discuția despre drift-ul accumulat (cca.\ $\SI{0.7}{\degree\per\second}$
pe cipul de bench, corectat de \texttt{slam\_toolbox} la fiecare potrivire

\section{Transformata Hough probabilistică}
\label{sec:hough}

Etapa a 5-a a pipeline-ului de procesare a hărților salvate
(\texttt{recon\_db.postprocess.hough\_line\_segments}) folosește o
variantă probabilistică a transformatei Hough~\cite{hough1962, dudahart1972,
matas2000probhough} pentru a detecta segmente de pereți în harta curățată.

Parametrizarea polară a unei linii:

\begin{equation}\label{eq:hough-rho}
    \rho = x \cos\theta + y \sin\theta
\end{equation}

\noindent unde $(\rho, \theta)$ definesc unic o linie în planul imaginii.
Acumulatorul Hough numără voturi în spațiul discretizat $(\rho, \theta)$,
iar liniile sunt extrase ca celule cu numărul de voturi peste un prag.
Etapa probabilistică extrage \textit{segmente} (nu linii infinite) prin
mersul de-a lungul liniei detectate și colectarea ,,curgerilor''
(\textit{runs}) de pixeli aprinși cu lungime minimă \texttt{min\_len} și
goluri maxime \texttt{max\_gap}.

[De dezvoltat: discuția algoritmului pas cu pas, dimensionarea
acumulatorului ($\rho \in [-\text{diag}, +\text{diag}]$,
$\theta \in [0, \pi)$), supresia non-maximelor.]

\section{Operațiuni morfologice pe imagini binare}
\label{sec:morfologie}

Etapele 2 și 3 ale pipeline-ului aplică operațiuni morfologice clasice
(\textit{eroziune}, \textit{dilatare}, \textit{deschidere},
\textit{închidere})~\cite{serra1982morpho, soille2003morpho} pe masca
binară de celule ocupate.

\begin{align}
    \text{Dilatare:}\quad A \oplus B &= \{ z \mid (\hat{B})_z \cap A \neq \emptyset \} \label{eq:dilation}\\
    \text{Eroziune:}\quad A \ominus B &= \{ z \mid (B)_z \subseteq A \} \label{eq:erosion}
\end{align}

Folosind un element structural 3$\times$3 cu 8-conectivitate:
\textbf{deschiderea} ($A \circ B = (A \ominus B) \oplus B$) elimină
zgomotele izolate, \textbf{închiderea} ($A \bullet B = (A \oplus B) \ominus B$)
închide spațiile mici dintre celulele ocupate.

[De dezvoltat: ilustrația vizuală cu exemple pe matrici 5$\times$5,
discuția gotcha-ului ,,opening cu 1 iterație erodează pereți de
1-celulă'' documentată în \texttt{test\_postprocess.py}.]

\section{Etichetarea componentelor conectate}
\label{sec:cc}

Etapa a 4-a aplică etichetare cu 8-conectivitate prin BFS
(\textit{breadth-first search})~\cite{rosenfeldpfaltz1966}. Fiecare
componentă conectată primește o etichetă unică; componentele mai mici
decât parametrul \texttt{min\_cluster\_size} (implicit 8) sunt clasificate
drept zgomot și ignorate.

[De dezvoltat: comparația algoritmului în două treceri (Rosenfeld-Pfaltz)
vs.\ flood-fill iterativ folosit în implementare. Justificarea iterativ
peste recursiv: evitarea limitelor de recursie Python pe hărți mari.]

\section{Filtrul median 3$\times$3}
\label{sec:median}

Etapa~1 aplică (opțional) un filtru median 3$\times$3~\cite{tukey1977eda}
pentru a elimina celulele rătăcite. Operația este definită ca:

\begin{equation}\label{eq:median}
    g(x, y) = \operatorname{median}\{f(x+i, y+j) \mid (i, j) \in W\}
\end{equation}

\noindent unde $W = \{-1, 0, +1\}^2$ este fereastra 3$\times$3.

\section{Verificarea integrității datelor cu CRC-8 Dallas/Maxim}
\label{sec:crc}

Cadrele binare transmise prin USB-CDC între ESP32 și Raspberry Pi sunt
protejate de un cod CRC-8 cu polinomul Dallas/Maxim~\cite{maxim1wirecrc,
linuxcrc8}:

\begin{equation}\label{eq:crc-poly}
    p(x) = x^8 + x^5 + x^4 + 1
\end{equation}

\noindent codificat ca $\mathtt{0x07}$ (cu bitul cel mai semnificativ
omis, conform convenției). Valoarea inițială este $\mathtt{0x00}$, fără
reflexie de intrare/ieșire și fără XOR final. Aceeași implementare este
folosită și de utilitarul \texttt{crc8} din nucleul Linux, ceea ce
permite verificarea ușoară a corectitudinii ambelor părți.
